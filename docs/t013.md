# T013 — Company & Multi-Company Architecture

- **Phase**: 1
- **Depends On**: T009
- **Estimated Effort**: 5 days

## What Is Being Built
`Company` model with group hierarchy (parent FK), `UserCompany` junction for multi-company access, company switcher infrastructure, and inter-company configuration. Master data is global; transactions are per-company. This task establishes the entire multi-company data architecture.

## How It Will Be Built

### Backend (Django)
- **Models** (`apps/core/models.py`):
  - `Company`: code (unique), name, parent FK (self, null = root company), is_group (bool — true = group company with children), registration_no, sst_no, address, city, state, postcode, country (default MY), phone, email, logo, base_currency (default MYR), inter_company_receivable FK → Account, inter_company_payable FK → Account, forex_realised_gain FK → Account, forex_realised_loss FK → Account, forex_unrealised_gain FK → Account, forex_unrealised_loss FK → Account, is_active
  - `UserCompany`: user FK → User, company FK → Company, is_default (bool), unique(user, company)
  - `CompanyGroup`: company FK, group FK → Company, effective_date (for historical tracking)

- **Migration**: creates tables, migrates existing `company_id` data

- **Service** (`apps/core/services/company_service.py`):
  - `get_user_companies(user)` — returns all companies user has access to
  - `get_user_default_company(user)` — returns default company
  - `set_user_default_company(user, company)` — sets default
  - `get_company_children(company)` — returns all child companies in group
  - `get_company_group(company)` — returns root group company
  - `assign_user_to_companies(user, company_ids, default_id)` — bulk assign
  - `unassign_user_from_company(user, company)` — remove access

- **API** (`apps/core/api/company_api.py`):
  - `GET /api/v1/companies/` — list user's accessible companies
  - `POST /api/v1/companies/` — create company (superadmin)
  - `PUT /api/v1/companies/{id}/` — update company
  - `GET /api/v1/companies/{id}/children/` — get child companies
  - `POST /api/v1/companies/{id}/children/` — add child company
  - `GET /api/v1/companies/current/` — get current active company
  - `POST /api/v1/companies/switch/` — switch active company
  - `PUT /api/v1/companies/default/` — set default company
  - `GET /api/v1/admin/user-companies/{user_id}/` — list user's company assignments
  - `POST /api/v1/admin/user-companies/{user_id}/` — assign companies to user
  - `DELETE /api/v1/admin/user-companies/{user_id}/{company_id}/` — unassign

- **Middleware** (`apps/core/middleware.py`):
  - `CompanyMiddleware` — reads `X-Company-Id` header from request, sets `request.company_id`
  - All transaction queries automatically filtered by `request.company_id`
  - Master data queries use assignment-based filtering

- **Context** (`apps/core/context.py`):
  - `current_company` — returns Company object from request
  - `user_companies` — returns QuerySet of user's accessible companies

### Frontend (React)
- **Company Switcher** (inline in `frontend/src/components/Layout/Sidebar.tsx`):
  - Below "pyERP" brand, always visible (no responsive hide)
  - Shows current company name on a dark badge
  - Dropdown to switch when multiple companies assigned
  - Single company → static badge (no dropdown)
- **Company Context** (`frontend/src/contexts/CompanyContext.tsx`):
  - `activeCompany`, `userCompanies`, `switchCompany()`, `setDefaultCompany()`
  - Persisted to localStorage
  - All API calls include `X-Company-Id` header via Axios interceptor
- **Admin Pages**:
  - `CompanyListPage` — company directory with group tree
  - `CompanyFormPage` — create/edit company
  - `UserCompanyAssignmentPage` — assign users to companies

### Data Architecture Rules
```
MASTER DATA (global, NO company_id FK):
  Item, Customer, Vendor, Employee, ChartOfAccount, TaxCode, UOM, Warehouse

JUNCTION TABLES (assignment + overrides):
  ItemCompany, CustomerCompany, VendorCompany, EmployeeCompany, AccountCompany

TRANSACTIONS (per-company, company_id FK):
  SupplierInvoice, CustomerInvoice, PurchaseOrder, SalesOrder,
  JournalEntry, StockMovement, WorkOrder, etc.

WAREHOUSES (per-company, company_id FK):
  Warehouse, BinLocation
```

### Default Company on First Login
- When user logs in for first time, auto-set their default company
- If user has no company assigned, show "No Company Access" page
- Admin can assign companies via User Management
