# T034b — Forex Gain/Loss Revaluation

- **Phase**: 2
- **Depends On**: T034a, T030, T031, T032, T033
- **Estimated Effort**: 3 days

## What Is Being Built
Forex gain/loss calculation engine: realized gain/loss on payment, unrealized gain/loss on period-end revaluation. GL entries for both. Semi-automatic revaluation process (user initiates, system calculates, user confirms). Company forex GL accounts.

## How It Will Be Built

### Backend (Django)
- **Model** (`apps/financial/models.py`):
  - `ForexRevaluationEntry`: id, period FK → FiscalPeriod, document_type (supplier_invoice/customer_invoice/credit_note), document_id (UUID), foreign_amount (decimal), original_rate (decimal), closing_rate (decimal), original_base (decimal — foreign × original_rate), revalued_base (decimal — foreign × closing_rate), difference (decimal — revalued - original), gain_loss (gain/loss), journal_entry FK → JournalEntry, company FK → Company, status (pending/posted), created_at

- **Service** (`apps/financial/services/forex_service.py`):
  - `calculate_realised_forex(invoice, payment_rate)` — payment base - invoice base = realised gain/loss
  - `post_realised_forex(invoice, payment, payment_rate, company)` — create GL entry for realised forex
  - `get_open_foreign_items(company, period)` — list open foreign currency invoices/POs
  - `calculate_unrealised_forex(company, period, closing_rates)` — calculate revaluation for all open items
  - `preview_revaluation(company, period)` — show preview of revaluation entries
  - `post_revaluation(company, period)` — post revaluation GL entries
  - `reverse_revaluation(company, period)` — reverse previous revaluation (if needed)

- **API** (`apps/financial/api/forex_api.py`):
  - `GET /api/v1/financial/forex/open-items/` — list open foreign currency items
  - `GET /api/v1/financial/forex/preview-revaluation/` — preview revaluation
  - `POST /api/v1/financial/forex/post-revaluation/` — post revaluation
  - `GET /api/v1/financial/forex/revaluation-history/` — past revaluations
  - `GET /api/v1/financial/forex/gain-loss-report/` — realised + unrealised summary

### Company Forex GL Accounts
```
Company (updated fields):
├── forex_realised_gain FK    → Account (7700)
├── forex_realised_loss FK    → Account (7800)
├── forex_unrealised_gain FK  → Account (7710)
├── forex_unrealised_loss FK  → Account (7810)
```

### GL Entries — Realised Forex (on payment)
```
Invoice: USD 10,000 @ 4.72 = MYR 47,200
Payment: USD 10,000 @ 4.75 = MYR 47,500
Realised Gain: MYR 300

DR Bank                                 47,500.00
CR Accounts Payable                     47,200.00
CR Realised Forex Gain (7700)             300.00
```

### GL Entries — Unrealised Forex (period-end revaluation)
```
Open Invoice: USD 10,000 @ 4.72 = MYR 47,200
Closing Rate: 4.75
Revalued: USD 10,000 @ 4.75 = MYR 47,500
Unrealised Gain: MYR 300

DR Accounts Payable                     47,200.00
DR Unrealised Forex Gain/Loss (7710)      300.00
CR Accounts Payable (revalued)          47,500.00
```

### Semi-Automatic Revaluation Flow
```
1. User clicks "Revalue Open Items" button at period-end
2. System finds all open foreign currency invoices/POs for the company
3. System fetches closing rate for each currency pair from ExchangeRate table
4. System calculates unrealized gain/loss for each item
5. System shows preview table:
   ┌─────────────┬────────────┬─────────┬─────────────┬────────────┬───────────┐
   │ Document    │ Foreign Amt│ Orig Rate│ Orig Base   │ Close Rate │ Gain/Loss │
   ├─────────────┼────────────┼─────────┼─────────────┼────────────┼───────────┤
   │ INV-001 USD │ 10,000.00  │ 4.72    │ 47,200.00   │ 4.75       │ +300.00   │
   │ PO-045 EUR  │ 5,000.00   │ 5.10    │ 25,500.00   │ 5.05       │ -250.00   │
   ├─────────────┴────────────┴─────────┴─────────────┴────────────┼───────────┤
   │ Total Unrealised Gain                                          │ +50.00    │
   └───────────────────────────────────────────────────────────────┴───────────┘
6. User reviews and clicks "Confirm Revaluation"
7. System posts GL entries for each item (or one summary entry)
8. System creates ForexRevaluationEntry records
9. System marks period as revalued
```
