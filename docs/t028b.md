# T028b — WIP Accounting (Work-in-Progress)

- **Phase**: 2
- **Depends On**: T072, T021
- **Estimated Effort**: 3 days

## What Is Being Built
Work-in-Progress (WIP) accounting for manufacturing. Track costs of unfinished goods (materials issued + labour booked + overhead applied). WIP is an asset on the Balance Sheet. Transfer WIP to Finished Goods on Work Order completion. WIP valuation report.

## How It Will Be Built

### Backend (Django)
- **Models** (`apps/financial/models.py`):
  - `WIPAccount`: id, work_order FK, period FK, material_cost, labour_cost, overhead_cost, total_cost, status (in_progress/completed/reversed), journal_entry FK, company FK, created_at
- **Service** (`apps/financial/services/wip_service.py`):
  - `record_material_issue(work_order_id, amount)` — DR WIP, CR Raw Material
  - `record_labour_booking(work_order_id, amount)` — DR WIP, CR Wages Payable
  - `record_overhead_application(work_order_id, amount)` — DR WIP, CR Overhead Control
  - `transfer_to_finished_goods(work_order_id)` — DR Finished Goods, CR WIP
  - `get_wip_valuation(company, as_at_date)` — total WIP across all work orders
  - `get_wip_detail(work_order_id)` — cost breakdown for a specific work order
- **API** (`apps/financial/api/wip_api.py`):
  - `GET /api/v1/financial/wip/` — WIP valuation report
  - `GET /api/v1/financial/wip/{work_order_id}/` — WIP detail for work order
  - `POST /api/v1/financial/wip/{work_order_id}/transfer/` — transfer to FG
