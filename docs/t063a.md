# T063a — Sales Returns

- **Phase**: 5
- **Depends On**: T063, T049
- **Estimated Effort**: 3 days

## What Is Being Built
Sales return processing from customers. Return authorisation workflow. Inspect returned goods. Credit note generation. Stock adjustment (returned to inventory or written off). Quality inspection on return. Return reason tracking.

## How It Will Be Built

### Backend (Django)
- **Models** (`apps/crm/models.py`):
  - `SalesReturn`: id, return_number, customer FK, original_invoice FK (optional), return_date, reason, status (requested/authorised/received/inspected/completed/cancelled), warehouse FK, inspector FK, gl_account FK, company FK, created_at
  - `SalesReturnLine`: return FK, item FK, quantity, uom FK, unit_cost, total_cost, condition (good/damaged/defective), disposition (restock/repair/write_off), lot_number, bin_location FK
- **Service** (`apps/crm/services/sales_return_service.py`):
  - `create_return(data)` — create return request
  - `authorise_return(return_id)` — approve return
  - `receive_return(return_id)` — receive goods, inspect, disposition
  - `post_return(return_id)` — create credit note, update stock, GL entries
  - `get_return_history(filters)` — past returns
- **GL Entries**:
  ```
  Return received and restocked:
  DR Sales Returns (contra-revenue)  5,000.00
  CR Accounts Receivable             5,000.00

  DR Inventory                       4,000.00
  CR Cost of Goods Sold              4,000.00

  Return with damaged goods (write-off):
  DR Loss on Damaged Goods             500.00
  CR Cost of Goods Sold                500.00
  ```

### Frontend (React)
- **Return Request Form**: customer, items, reason
- **Return List Page**: all returns with status
- **Inspection Page**: disposition decision (restock/repair/write-off)
- **Return Reason Dashboard**: analysis of return reasons
