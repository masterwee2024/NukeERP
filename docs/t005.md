# T005 — Dynamic Menu System

- **Phase**: 0
- **Depends On**: T001
- **Estimated Effort**: 3 days

## What Is Being Built
A database-driven navigation menu system. Menu items are stored as records in a `Menu` table with parent-child nesting (self-referencing FK). Roles are linked to menus via a `MenuRole` junction table. The API returns a filtered tree based on the user's permissions. The frontend sidebar renders dynamically from this API — no menu items are hardcoded in React.

## How It Will Be Built

### Backend (Django)
- **Models** (`apps/core/models.py`):
  - `Menu`: name, slug (unique), icon (Lucide icon name), url, parent FK (self-referencing, null=root), sort_order, permission_codename, is_active, level (0=root, 1=sub, 2=sub-sub), module (grouping tag)
  - `MenuRole`: menu FK, role FK (unique together)
- **Migration**: `apps/core/migrations/0001_initial.py`
- **Seed data**: `apps/core/management/commands/seed_menus.py` — inserts full menu tree (50+ items)
- **API** (`apps/core/api/menu_api.py`):
  - `GET /api/v1/menus/` — returns filtered tree for current user
  - `POST /api/v1/menus/` — create menu item (admin only)
  - `PUT /api/v1/menus/{id}/` — update menu item (admin only)
  - `DELETE /api/v1/menus/{id}/` — soft delete / deactivate
  - `GET /api/v1/admin/menus/` — full tree with role assignments (admin view)

### Frontend (React)
- **Hook**: `useMenu()` in `frontend/src/hooks/useMenu.ts` — fetches menu tree, builds nested structure
- **Types**: `frontend/src/types/menu.ts` — `MenuItem`, `MenuTree` interfaces
