# T009f — Transaction Migration

- **Phase**: 0
- **Depends On**: T009d, T009e
- **Estimated Effort**: 3 days

## What Is Being Built
Import pending and historical transactions — open purchase orders, open sales orders, open GRNs, historical journal entries, historical invoices. Companies can either start fresh (opening balances only) or migrate pending/historical data for continuity.

## How It Will Be Built

### Backend (Django)
- **Service** (`apps/core/services/transaction_migration_service.py`):
  - `import_pending_pos(data)` — create open POs with line items
  - `import_pending_sos(data)` — create open sales orders with line items
  - `import_pending_grns(data)` — create open GRNs
  - `import_historical_journals(data)` — create historical journal entries (status: posted, no GL impact)
  - `import_historical_invoices(data)` — create historical AP/AR invoices
  - `validate_references(data)` — check supplier, customer, item codes exist
  - `get_migration_summary(company)` — summary of all migrated transactions
  - `rollback_transactions(company)` — remove all migrated transactions

- **Migration Options**:
  ```
  Option A: Fresh Start (Recommended)
  ├── Import master data (T009d)
  ├── Import opening balances (T009e)
  ├── Do NOT import historical transactions
  ├── Start fresh from go-live date
  └── Keep old system for reference only

  Option B: Full Migration
  ├── Import master data (T009d)
  ├── Import opening balances (T009e)
  ├── Import pending transactions (this task)
  ├── Import historical transactions (this task)
  ├── Continue seamlessly from old system
  └── More complex but complete continuity
  ```

- **CSV Templates**:
  | Template | Columns |
  |---|---|
  | Open POs | po_number, supplier_code, order_date, expected_date, item_code, quantity, unit_price, currency |
  | Open Sales Orders | so_number, customer_code, order_date, required_date, item_code, quantity, unit_price, currency |
  | Historical Journals | entry_number, date, account_code, description, debit, credit, period |
  | Historical AP Invoices | supplier_code, invoice_no, invoice_date, due_date, amount, currency, status |
  | Historical AR Invoices | customer_code, invoice_no, invoice_date, due_date, amount, currency, status |

### Frontend (React)
- **TransactionMigrationPage**: choose migration option (fresh start vs full)
- **PendingTransactionImport**: CSV upload for open POs, SOs
- **HistoricalImport**: CSV upload for historical journals, invoices
- **MigrationSummary**: summary of all migrated data
- **MigrationReport**: detailed report with record counts

### Migration Strategy
```
For Fresh Start (Option A):
1. Import master data (COA, items, customers, vendors, employees)
2. Import opening balances (GL, AP, AR, inventory, assets)
3. Set go-live date
4. Start entering new transactions
5. Keep old system read-only for reference

For Full Migration (Option B):
1. Import master data (COA, items, customers, vendors, employees)
2. Import historical transactions (journals, invoices, payments)
3. Import pending transactions (open POs, SOs, invoices)
4. Import opening balances (GL, AP, AR, inventory, assets)
5. Set go-live date
6. Continue seamlessly from old system
```

### Historical Transaction Handling
```
Historical transactions are imported with:
├── status = "posted" (historical, read-only)
├── No GL impact (already posted in old system)
├── Linked to correct periods
├── Preserved for reporting and audit trail
└── Cannot be edited (historical integrity)
```
