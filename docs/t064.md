# T063 — After-Sales / RMA

- **Phase**: 5
- **Depends On**: T055
- **Estimated Effort**: 3 days

## What Is Being Built
Return Merchandise Authorization (RMA): RMA number, reason, items. Receipt of returned goods → inspection → credit note/repair/replace. Service ticket tracking. Warranty validation by serial number.

## How It Will Be Built

### Backend (Django)
- **Models** (`apps/crm/models.py`):
  - `RMA`: rma_number, customer FK, sales_order FK (optional), reason, status (requested/approved/received/inspected/resolved/closed), created_at, company FK
  - `RMALine`: rma FK, item FK, quantity, serial_number, condition (damaged/defective/undesired), resolution (credit_note/repair/replace/refund)
  - `ServiceTicket`: customer FK, subject, description, status (open/in_progress/resolved/closed), priority, assigned_to FK, company FK
- **Service**: CRUD, approval, inspection, resolution processing (credit note or replacement order)
- **API**: RMA CRUD + approve + inspect + resolve, service ticket CRUD

## Deliverables Checklist
- [ ] `RMA`, `RMALine`, `ServiceTicket` models
- [ ] RMA workflow (request → approve → receive → inspect → resolve)
- [ ] Resolution options: credit note, repair, replace, refund
- [ ] Warranty validation by serial number
- [ ] Service ticket tracking
- [ ] React RMA and service ticket pages
- [ ] All actions use `useConfirm()` dialog

## Success Criteria
- [ ] RMA request creates record with correct status
- [ ] Approval advances workflow
- [ ] Resolution creates credit note or replacement order
- [ ] Warranty check validates serial number against original sale
- [ ] All tests pass
