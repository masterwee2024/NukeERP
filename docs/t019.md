# T019 — Notification Framework

- **Phase**: 1
- **Depends On**: T009
- **Estimated Effort**: 5 days

## What Is Being Built
In-app notification bell + email notifications. Notification types configurable (approval request, leave approved, invoice posted, etc.). Mark-as-read, notification centre page. Celery task for email dispatch.

## How It Will Be Built

### Backend (Django)
- **Models** (`apps/core/models.py`):
  - `NotificationType`: name, slug, email_template, in_app_template, is_active
  - `Notification`: notification_type FK, recipient FK (User), title, message, link (URL to relevant page), is_read, read_at, created_at, company FK
  - `PushSubscription`: user FK, endpoint (URL), p256dh (key), auth (key), user_agent, is_active, created_at
  - `ApprovalToken`: execution FK, user FK, token (unique), action (approve/reject), expires_at, is_used, used_at, company FK
- **Service** (`apps/core/services/notification_service.py`):
  - `send_notification(recipient, notification_type, title, message, link)` — creates in-app + queues email
  - `mark_as_read(notification_id)` — marks as read
  - `get_unread_count(user)` — for bell badge
- **Celery Tasks**:
  - `send_notification_email` — async email dispatch
  - `send_push_notification` — async PWA push via Web Push Protocol
  - `send_approval_email` — email with approve/reject links (secure tokens)
  - `cleanup_expired_tokens` — remove expired approval tokens daily
- **WebSocket Consumer** (`apps/core/consumers.py`):
  - `NotificationConsumer` — real-time notification delivery via WebSocket
  - User-specific channel: `notifications_{user_id}`
  - Handles: new_notification, mark_read, unread_count_update
- **ASGI Config** (`pyerp/asgi.py`):
  - WebSocket routing alongside HTTP
  - Channel layers backed by Redis
- **Push Service** (`apps/core/services/push_service.py`):
  - `subscribe_push(user, subscription)` — save push subscription
  - `unsubscribe_push(user)` — remove push subscription
  - `send_push(user, title, body, url)` — send push to all user's devices
- **Email Approval Service** (`apps/core/services/email_approval_service.py`):
  - `generate_approval_token(execution, user, action)` — create secure JWT token (7-day expiry, single-use)
  - `send_approval_email(execution, approver)` — send email with approve/reject links
  - `process_email_approval(token, action)` — validate token, process approval, mark used
- **API** (`apps/core/api/notification_api.py`):
  - `GET /api/v1/notifications/` — user's notifications (paginated, newest first)
  - `GET /api/v1/notifications/unread-count/` — unread count for badge
  - `PUT /api/v1/notifications/{id}/read/` — mark as read
  - `PUT /api/v1/notifications/read-all/` — mark all as read
  - `POST /api/v1/notifications/push/subscribe/` — register push subscription
  - `DELETE /api/v1/notifications/push/unsubscribe/` — remove push subscription
  - `GET /api/v1/notifications/push/status/` — check push permission status
  - `GET /api/v1/approvals/execute?token=xxx&action=approve|reject` — email approve/reject endpoint

### Frontend (React)
- **Notification Bell**: `frontend/src/components/Layout/NotificationBell.tsx`
  - Bell icon with red badge showing unread count
  - Dropdown showing latest 10 notifications
  - Click to mark as read + navigate to link
- **Notification Centre Page**: full notification list with filters (read/unread, type, date)
