# T014 — Role-Based Access Control (RBAC)

- **Phase**: 1
- **Depends On**: T005, T008
- **Estimated Effort**: 3 days

## What Is Being Built
Custom permission model: `Role` → `Permission` (module + action). Assign roles to users. API decorator `@permission_required` enforces access. UI route guards hide unauthorized pages. `MenuRole` junction from T005 links roles to menu visibility.

## How It Will Be Built

### Backend (Django)
- **Models** (`apps/core/models.py`):
  - `Role`: name (unique), description, is_active, is_system (superadmin role cannot be deleted)
  - `Permission`: module (choices: financial/scm/crm/mrp/hrm/admin), action (choices: view/create/update/delete/approve/post/export), codename (auto-generated: `{module}_{action}`)
  - `RolePermission`: role FK, permission FK (unique together)
  - `UserRole`: user FK, role FK (unique together)
- **API** (`apps/core/api/rbac_api.py`):
  - `GET /api/v1/admin/roles/` — list roles with permission count
  - `POST /api/v1/admin/roles/` — create role
  - `PUT /api/v1/admin/roles/{id}/` — update role (name, description)
  - `PUT /api/v1/admin/roles/{id}/permissions/` — assign permissions (list of permission IDs)
  - `PUT /api/v1/admin/users/{id}/roles/` — assign roles to user
  - `GET /api/v1/admin/permissions/` — list all available permissions
- **Decorator**: `@permission_required("financial_approve")` on API views
- **Middleware**: injects `user.permissions` set into request context

### Frontend (React)
- **Hook**: `usePermission()` — check if user has specific permission
- **Route Guard**: `ProtectedRoute` component — wraps routes, redirects if unauthorized
- **RBAC Admin Page**: Role list → select role → checkbox grid of permissions (module × action)
- **User Role Assignment**: User form gains "Roles" multi-select
