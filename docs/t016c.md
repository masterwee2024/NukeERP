# T016c — Centralized Approval Page + Mobile Notifications

- **Phase**: 1
- **Depends On**: T016, T019
- **Estimated Effort**: 4 days

## What Is Being Built
Centralized approval page where users see ALL pending approvals across all modules. Full transaction context for informed decisions. Quick approve/reject with comment. Mobile push notifications (PWA) and email notifications with approve/reject links (process directly from email without opening app).

### UI Delivery
- **Route**: `/app/approvals`
- **Page**: `frontend/src/pages/admin/ApprovalCenterPage.tsx`
- **Sidebar**: Under Administration > Approvals Center (slug: `admin-approvals`, icon: `CheckSquare`)

## How It Will Be Built

### Backend (Django)
- **API** (`apps/core/api/approval_center_api.py`):
  - `GET /api/v1/approval-center/` — all pending approvals for current user, filtered by company access
  - `GET /api/v1/approval-center/{id}/context/` — full document data + approval history + workflow info
  - `POST /api/v1/approval-center/{id}/quick-approve/` — approve with optional comment
  - `POST /api/v1/approval-center/{id}/quick-reject/` — reject with required comment
  - `POST /api/v1/approval-center/{id}/delegate/` — delegate to another user
  - `GET /api/v1/approval-center/stats/` — count by module/type, aging, overdue

- **Email Approve/Reject** (`apps/core/services/email_approval_service.py`):
  - Generate secure token (JWT, 7-day expiry, single-use)
  - Token contains: execution_id, user_id, company_id, action (approve/reject)
  - API endpoint: `GET /api/v1/approvals/execute?token=xxx&action=approve|reject`
  - Validate token → process approval → show result page
  - No login required for email-based approval (token auth)

- **Mobile Push** (`apps/core/services/push_notification_service.py`):
  - PWA Push API integration (Web Push Protocol)
  - User subscribes to push on login (service worker registration)
  - Send push on new approval request
  - Push includes: title, body, action_url (deep link to approval page)
  - Click notification → opens app to approval page

### Frontend (React)
- **CentralizedApprovalPage** (`frontend/src/components/approval/CentralizedApprovalPage.tsx`):
  - Dashboard header: total pending, overdue, by module stats
  - Filter bar: module, document type, date range, amount range, requester
  - Approval list: card-based layout with key info per item
  - Quick actions: approve/reject buttons directly on card
  - Click to expand: full document context (line items, history, comments)
  - Batch approve: select multiple → approve all at once

- **ApprovalContextPanel** (`frontend/src/components/approval/ApprovalContextPanel.tsx`):
  - Shows full transaction details without leaving approval page
  - Document header (number, date, amount, requester)
  - Line items table
  - Previous approval steps with comments
  - Related documents (linked PO, GRN, etc.)

- **ApprovalStatsWidget** (`frontend/src/components/approval/ApprovalStatsWidget.tsx`):
  - Pending count by module
  - Overdue items (past timeout)
  - Average approval time
  - Can be placed on dashboard

- **PushNotificationSetup** (`frontend/src/components/notifications/PushNotificationSetup.tsx`):
  - Request push permission on first login
  - Register service worker
  - Store push subscription
  - Toggle push notifications on/off in settings

- **EmailApprovalResultPage** (`frontend/src/pages/EmailApprovalResultPage.tsx`):
  - Shown after user clicks email approve/reject link
  - Displays: document summary, approval result, timestamp
  - "View in App" button to open full app
  - "Back to approvals" link

### PWA Push Notification Flow
```
1. User logs in → service worker registered
2. Push subscription saved to backend
3. New approval request → backend sends push
4. Push appears on mobile/desktop even when app is closed
5. User clicks push → opens app to approval page
6. User approves/rejects
```

### Email Approve/Reject Flow
```
1. New approval request → email sent with approve/reject links
2. User opens email → clicks "Approve" link
3. Link opens API endpoint with secure token
4. Token validated → approval processed
5. Result page shown: "PO-00123 approved successfully"
6. No login required (token-based auth)
```
