# T016d — Approval Workflow Policy

- **Phase**: 1
- **Depends On**: T016
- **Estimated Effort**: 2 days

## What Is Being Built
Approval policy engine that auto-routes transactions to the correct workflow based on conditions. Policies evaluate document data (amount, department, vendor, etc.) and select the matching workflow. Priority-based evaluation when multiple policies match. Company-scoped policies.

## How It Will Be Built

### Backend (Django)
- **Model** (`apps/core/models.py`):
  - `ApprovalPolicy`: name, workflow FK → WorkflowDefinition, module, document_type, conditions (JSON), priority (int), is_active, company FK (null = global), created_at
  - `ApprovalPolicyCondition`: policy FK, field_name (from document model), operator (> | < | >= | <= | == | != | in | not_in | between), value (JSON), value_to (for between)

- **Condition Evaluation** (`apps/core/services/policy_service.py`):
  - `evaluate_policy(policy, document_data)` — check all conditions against document fields, return True if all match (AND logic)
  - `get_applicable_policy(module, document_type, document_data, company)` — find matching policy with highest priority (lowest number)
  - `evaluate_condition(condition, document_data)` — evaluate single condition

- **API** (`apps/core/api/policy_api.py`):
  - `GET /api/v1/admin/approval-policies/` — list policies
  - `POST /api/v1/admin/approval-policies/` — create policy
  - `PUT /api/v1/admin/approval-policies/{id}/` — update policy
  - `DELETE /api/v1/admin/approval-policies/{id}/` — deactivate policy
  - `POST /api/v1/admin/approval-policies/test/` — test policy against sample data

### Policy Evaluation Flow
```
1. Transaction submitted for approval
2. Policy engine evaluates all active policies for (module, document_type, company)
3. For each policy, evaluate conditions against document data
4. If multiple policies match, select one with lowest priority number
5. If no policy matches, use default workflow (if configured)
6. If no default, transaction can be approved manually or rejected
```

### Condition Examples
```json
// High-value PO (amount >= RM50,000)
{
  "field": "total_amount",
  "operator": ">=",
  "value": 50000
}

// Department-specific
{
  "field": "department",
  "operator": "==",
  "value": "procurement"
}

// Combined (AND logic)
[
  {"field": "total_amount", "operator": ">=", "value": 50000},
  {"field": "department", "operator": "==", "value": "procurement"}
]

// Between range
{
  "field": "total_amount",
  "operator": "between",
  "value": 10000,
  "value_to": 50000
}
```

### Policy Admin UI
- Policy list page: module filter, document type filter, priority order
- Policy form: conditions builder (add/remove conditions, field/operator/value)
- Test mode: enter sample document data → see which workflow would be selected
- Drag to reorder priorities

### Company Scoping
- Global policies (company=null) apply to all companies
- Company-specific policies override global policies
- Evaluation order: company-specific first, then global
