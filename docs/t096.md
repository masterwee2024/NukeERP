# T096 — Performance Optimization

- **Phase**: 8
- **Depends On**: T089
- **Estimated Effort**: 4 days

## What Is Being Built
Django: query optimization (select_related, prefetch_related), DB indexing review, cached views (Redis). React: code splitting (React.lazy), virtual scrolling for large lists, memo optimization, bundle size analysis. Lighthouse score target: 90+.

## How It Will Be Built

### Backend (Django)
- Query review: identify N+1 queries, add select_related/prefetch_related
- DB index review: add indexes on frequently queried fields
- Redis caching for expensive reports and dashboard queries
- `django-debug-toolbar` for query analysis
- **PgBocker**: Transaction mode, pool size 20, max client 500 (configured in T002)
- **Database Indexing Policy**:
  - All ForeignKey fields: `db_index=True`
  - All status/choice fields: `db_index=True`
  - All date fields used in filters: `db_index=True`
  - Composite indexes for common query patterns (status+date, company+status)
  - GIN indexes for full-text search fields
  - Review with `EXPLAIN ANALYZE` on all critical queries

### Frontend (React)
- Code splitting with `React.lazy` + `Suspense` per route
- Virtual scrolling (react-virtualized or react-window) for large tables
- `React.memo` for expensive components
- Bundle analysis with `rollup-plugin-visualizer`
- Image optimization (lazy loading, WebP)
- **Debouncing**: `useDebounce` hook on all search inputs (300ms delay)
- **Virtual scrolling**: react-window for lists > 100 items
- **Code splitting**: React.lazy for route-level components
- **Bundle analysis**: rollup-plugin-visualizer to identify large dependencies
