# T065c — Portal Shared Components & Security

- **Phase**: 5
- **Depends On**: T008, T013
- **Estimated Effort**: 4 days

## What Is Being Built
Shared portal infrastructure: portal layout, authentication (JWT for portal users), navigation, notifications, responsive design, and critical security boundary between internal ERP and external portals. Data isolation enforcement. Internal/external channel security.

## How It Will Be Built

### Backend (Django)
- **Portal Authentication** (`apps/portal/auth.py`):
  - Separate JWT for portal users (shorter TTL: 2 hours)
  - Portal user linked to Customer or Vendor record
  - Portal login endpoint (separate from internal login)
  - Password reset for portal users
  - Session management (single device or multi-device)

- **Security Middleware** (`apps/portal/middleware.py`):
  - `PortalSecurityMiddleware` — enforces data isolation
  - Internal users: block `/portal/*` routes
  - External users: block `/app/*` routes
  - All portal API queries scoped to entity_id (customer or vendor)
  - No cross-entity data leakage

- **Portal API Base** (`apps/portal/api/base.py`):
  - Base portal view with entity scoping
  - Auto-inject entity_id filter on all queries
  - Rate limiting on portal endpoints
  - Audit logging for portal actions

### Frontend (React)
- **PortalLayout** (`frontend/src/components/portal/PortalLayout.tsx`):
  - Shared layout for client and supplier portals
  - Header: portal logo, notifications, messaging, profile dropdown
  - Sidebar: navigation (different per portal type)
  - Content area
  - Mobile: hamburger menu, full-width content

- **PortalAuth** (`frontend/src/components/portal/PortalAuth.tsx`):
  - Separate login page for portal users
  - Register page (if enabled)
  - Forgot password page
  - Portal-specific branding

- **PortalNavigation** (`frontend/src/components/portal/PortalNavigation.tsx`):
  - Navigation items differ by portal type
  - Client: Dashboard, Documents, Payments, Support, Messaging
  - Supplier: Dashboard, Purchase Orders, Invoices, RFQs, Deliveries, Payments, Messaging
  - Active item highlighting

- **PortalNotifications** (`frontend/src/components/portal/PortalNotifications.tsx`):
  - Notification bell (same as internal)
  - Portal-specific notifications (invoice received, PO updated, etc.)

- **ResponsiveDesign** (`frontend/src/components/portal/ResponsiveDesign.tsx`):
  - Same responsive rules as internal (no horizontal scroll)
  - Mobile-first approach
  - Touch-optimized interactions

### Security Architecture
```
Internal ERP (/app/*)
├── Authentication: JWT (employee login, 8-hour TTL)
├── Data access: Full company data
├── Channel access: All internal channels
├── Portal access: BLOCKED (403)

Client Portal (/portal/client/*)
├── Authentication: JWT (customer login, 2-hour TTL)
├── Data access: ONLY own customer data
├── Channel access: ONLY dedicated client channel
├── Internal access: BLOCKED (403)
├── Cross-client: BLOCKED (no visibility)

Supplier Portal (/portal/supplier/*)
├── Authentication: JWT (vendor login, 2-hour TTL)
├── Data access: ONLY own vendor data
├── Channel access: ONLY dedicated supplier channel
├── Internal access: BLOCKED (403)
├── Cross-supplier: BLOCKED (no visibility)
```
