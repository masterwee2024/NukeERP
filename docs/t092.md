# T091 — LHDN e-Invoicing Integration

- **Phase**: 8
- **Depends On**: T027, T029, T059
- **Estimated Effort**: 5 days

## What Is Being Built
MyInvois API integration: invoice submission, validation, digital signature. e-Invoice status tracking (submitted/valid/rejected/cancelled). QR code on invoice PDF. Credit note & debit note e-invoice. Bulk submission. Error handling & retry.

## How It Will Be Built

### Backend (Django)
- **Models** (`apps/financial/models.py`):
  - `EInvoice`: invoice FK ( SupplierInvoice or CustomerInvoice), uuid (LHDN-assigned), submission_date, validation_status, qr_code_data, lhdn_response (JSONField), error_message, retry_count
- **Service** (`apps/financial/services/einvoice_service.py`):
  - `submit_einvoice(invoice_id)` — prepare payload per LHDN schema, sign, submit via API
  - `validate_einvoice(uuid)` — check status with LHDN
  - `handle_callback(callback_data)` — process validation result
  - `generate_qr_code(invoice_id)` — embed QR in PDF
  - `bulk_submit(invoice_ids)` — batch submission via Celery
- **API**: submit, validate, callback webhook, bulk submit, status check
- **Celery Tasks**: retry failed submissions, poll status

### LHDN API Integration Points
- **Submit**: POST to MyInvois API with signed invoice data
- **Validate**: GET status by UUID
- **Cancel**: POST cancel request
- **QR Code**: embed in invoice PDF (base64)

### Frontend (React)
- `EInvoiceStatusPage` — submission status dashboard
- `EInvoiceRetryPage` — retry failed submissions
- `EInvoiceBulkPage` — bulk submission interface
