# T200 — Property Management: Property Register

- **Phase**: 2
- **Depends On**: T009b, T013
- **Estimated Effort**: 3 days

## What Is Being Built
Property portfolio register — property types (residential/commercial/industrial/mixed), property details, unit hierarchy, amenities, property valuations. Core entity for all property management functions.

## How It Will Be Built

### Backend (Django)
- **Models** (`apps/property/models.py`):
  - `PropertyType`: id, name (residential/commercial/industrial/mixed), description, company FK
  - `Property`: id, code, name, property_type FK, address, city, state, postcode, country, total_units, total_floor_area_sqft, purchase_date, purchase_price, current_valuation, property_manager FK → Employee, GL_account_revenue FK, GL_account_expense FK, status (active/under_maintenance/retired), company FK, created_at, updated_at, version
  - `Unit`: id, unit_number, property FK, floor, type (office/retail/warehouse/parking/other), area_sqft, monthly_rental, status (vacant/occupied/under_maintenance), tenant FK (current), company FK
  - `PropertyAmenity`: id, property FK, name, description, is_shared (bool), company FK
  - `PropertyValuation`: id, property FK, valuation_date, valuation_amount, valuation_type (purchase/current_market/independent), notes, company FK
- **Service**: CRUD, property tree, unit management, valuation tracking
- **API**: Property CRUD, unit CRUD, valuation CRUD, property tree

### Frontend (React)
- **Property List Page**: all properties with status, units, occupancy
- **Property Form Page**: create/edit with tabs (details, units, amenities, valuations)
- **Property Detail Page**: overview, unit grid, valuation history
- **Unit Management Page**: unit list with status, tenant link
