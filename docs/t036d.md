# T036d — Corrective Maintenance & Work Orders

- **Phase**: 3
- **Depends On**: T036c
- **Estimated Effort**: 5 days

## What Is Being Built
Corrective maintenance for breakdown repair and ad-hoc maintenance requests. Full work order lifecycle: request → approve → schedule → assign → execute (labour + parts) → close. Downtime tracking. Root cause analysis. Cost tracking per work order (labour + parts + external). Integration with inventory for spare parts.

## How It Will Be Built

### Backend (Django)
- **Models** (`apps/assets/models.py`):
  - `MaintenanceWorkOrder`: id, wo_number, asset FK, schedule FK (optional — if preventive), type (preventive/corrective/breakdown/emergency), description, priority (low/medium/high/critical), status (draft/approved/in_progress/on_hold/completed/closed), requested_by FK, assigned_to FK (employee), assigned_team FK (optional), vendor FK (optional — outsourced), planned_start_date, planned_end_date, actual_start_date, actual_end_date, downtime_hours, downtime_reason, root_cause, corrective_action, lessons_learned, total_labour_cost, total_parts_cost, total_external_cost, total_cost, gl_account FK, company FK, created_at, updated_at
  - `MaintenanceWorkOrderLine`: wo FK, line_type (labour/part/external_service), employee FK (for labour), item FK (for parts — from inventory), vendor FK (for external), quantity, unit_cost, total_cost, notes, sort_order
  - `MaintenanceDowntime`: id, wo FK, asset FK, start_time, end_time, duration_hours, reason, category (planned/unplanned/emergency)
  - `RootCauseCategory`: id, name, code, description, company FK
- **Service** (`apps/assets/services/corrective_maintenance_service.py`):
  - `create_work_order(data)` — create WO with lines
  - `approve_work_order(wo_id)` — approve with confirmation
  - `assign_work_order(wo_id, assignee)` — assign to team/vendor
  - `start_work(wo_id)` — set in_progress, record actual start
  - `add_labour(wo_id, employee, hours, rate)` — add labour line
  - `add_parts(wo_id, item, qty)` — add parts line, reduce inventory
  - `add_external(wo_id, vendor, amount)` — add external service line
  - `complete_work(wo_id)` — set completed, record downtime, root cause
  - `close_work(wo_id)` — final review, close
  - `get_cost_summary(wo_id)` — labour + parts + external = total
  - `get_asset_maintenance_history(asset_id)` — all WOs for asset
  - `get_maintenance_cost_report(company, period)` — cost by asset, type, team
- **API** (`apps/assets/api/work_order_api.py`):
  - WO CRUD, approve, assign, start, add lines, complete, close, history, cost report

### Frontend (React)
- **Work Order List Page**: all WOs with status, priority, asset, assigned to
- **Work Order Form Page**: create/edit WO with line items
- **Work Order Detail Page**: status timeline, labour/parts/external lines, cost summary, downtime log
- **Work Order Board**: Kanban view (approved → in_progress → completed → closed)
- **Maintenance History Page**: per-asset maintenance log with cost trend
- **Cost Report Page**: maintenance cost by asset, category, period
