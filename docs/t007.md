# T007 — Confirm Dialog & Core UI Components

- **Phase**: 0
- **Depends On**: T001
- **Estimated Effort**: 4 days

## What Is Being Built
A single, reusable `ConfirmDialog` React component and `useConfirm()` hook that standardizes confirmation across the entire application. Every create, update, delete, post, void, and approve action must use this hook — no exceptions. No `window.confirm()` anywhere in the codebase.

## How It Will Be Built

### Frontend (React)
- **Component**: `frontend/src/components/ui/ConfirmDialog.tsx`
  - Modal overlay with backdrop blur
  - Title, message, confirm/cancel buttons
  - Variants: `danger` (red), `warning` (amber), `info` (blue)
  - Loading state while async operation is in progress
  - Focus trap: focus moves to dialog on open, returns to trigger on close
  - Keyboard: Escape to cancel, Enter to confirm
  - Accessible: `role="dialog"`, `aria-modal`, `aria-labelledby`
  - Responsive: `max-w-[calc(100vw-2rem)]`, no horizontal overflow

- **Hook**: `frontend/src/hooks/useConfirm.ts`
  ```typescript
  const { confirm } = useConfirm();
  // Usage: confirm({ title, message, variant }) → Promise<boolean>
  ```

- **Approval Hook**: `frontend/src/hooks/useApproval.ts`
  ```typescript
  const { submit, approve, reject, delegate, isPending, history } = useApproval();

  // Submit for approval (triggers workflow):
  await submit("purchase_order", poId, { total_amount: 125000 });

  // Approve a pending request:
  await approve(executionId, "Approved within budget");

  // Reject:
  await reject(executionId, "Over budget — please revise");

  // Delegate to another user:
  await delegate(executionId, targetUserId, "On leave — please handle");

  // All actions show ConfirmDialog automatically before executing
  ```

- **ConfirmProvider**: `frontend/src/providers/ConfirmProvider.tsx`
  - Context provider wrapping the app
  - Manages dialog state (open/close, config, resolve function)
  - `useConfirm()` returns `{ confirm }` which returns a Promise<boolean>
