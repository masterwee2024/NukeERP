# T031 — Accounts Payable: Payment Runs

- **Phase**: 2
- **Depends On**: T027
- **Estimated Effort**: 4 days

## What Is Being Built
Payment proposal generation (select invoices by due date). Payment method (cheque/bank transfer). Generate payment file (EFT/IBG format). Allocate payments to invoices. Supplier statement.

## How It Will Be Built

### Backend (Django)
- **Models**:
  - `Payment`: payment_number, date, supplier FK, bank_account FK, method (cheque/bank_transfer/cash), amount, reference, status (draft/posted/cancelled), company FK
  - `PaymentAllocation`: payment FK, invoice FK, amount_allocated
- **Service**: `create_payment()`, `post_payment()` (GL: DR AP control, CR bank), `allocate_payment()`, `generate_payment_file()`, realised forex gain/loss calculation when payment rate ≠ invoice rate
- **API**: Payment CRUD + post + allocate + file generation

### Frontend (React)
- `PaymentRunPage` — select invoices, generate proposal, review, submit
- `PaymentListPage` — payment history with filters
- `SupplierStatementPage` — outstanding invoices and payments for a supplier

- [ ] Payment run selects correct invoices by due date
- [ ] Posting payment creates correct GL entries
- [ ] Payment allocation reduces invoice outstanding balance
- [ ] Payment file format is correct for bank submission
- [ ] Supplier statement shows accurate outstanding
- [ ] Payment at different rate than invoice calculates realised forex gain/loss

- [ ] All tests pass
