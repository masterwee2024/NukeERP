# T029b — Configurable Aging Buckets

- **Phase**: 2
- **Depends On**: T029
- **Estimated Effort**: 1 day

## What Is Being Built
Configurable aging bucket definitions per company. Instead of hardcoded 30/60/90/120 buckets, companies can define their own aging periods (e.g., 7/14/30/60/90 or 30/60/90/120/180). Aging reports use company-specific buckets.

## How It Will Be Built

### Backend (Django)
- **Model** (`apps/financial/models.py`):
  - `AgingBucket`: id, company FK, name (e.g., "Current", "1-30 Days", "31-60 Days"), days_from (int), days_to (int), sort_order, is_active
- **Seed Data**: Default buckets: Current (0-30), 31-60, 61-90, 91-120, 120+
- **Service** (`apps/financial/services/aging_service.py`):
  - `get_aging_buckets(company)` — get configured buckets for company
  - `calculate_aging(invoices, buckets)` — assign invoices to buckets based on due date
  - `get_aging_report(company, as_at_date, bucket_type)` — AR or AP aging
- **API** (`apps/core/api/aging_api.py`):
  - `GET /api/v1/financial/aging-buckets/` — list buckets
  - `PUT /api/v1/financial/aging-buckets/` — update bucket config
  - `GET /api/v1/financial/reports/aging/{type}/` — aging report (type: ar/ap)
