# T002 — Docker Compose Dev Environment

- **Phase**: 0
- **Depends On**: T001
- **Estimated Effort**: 3 days

## What Is Being Built
A `docker-compose.yml` that runs the full dev stack: PostgreSQL 16, Redis, Django app server (with hot-reload), React Vite dev server (with hot-reload), and MinIO for file storage. Developers run one command to start everything.

## How It Will Be Built

### Docker Compose Services
- `db`: PostgreSQL 16, persistent volume, health check
- `redis`: Redis 7, health check
- `django`: Python 3.12-slim, mount `./apps` for hot-reload, depends on db + redis
- `frontend`: Node 22-alpine, mount `./frontend` for hot-reload via Vite
- `minio`: MinIO S3-compatible storage, persistent volume
- `pgbouncer`: PgBocker connection pooler (transaction mode, 20 pool size, 500 max client connections)

### Configuration
- `.env` for all secrets (DB password, Redis URL, MINIO keys)
- `docker-compose.override.yml` for dev-specific settings (ports, volumes)
- Django `settings.py` reads from environment via `django-environ`

### Volumes
- `postgres_data`: persistent DB storage
- `minio_data`: persistent file storage
- `./apps:/app/apps` — Django code mount for hot-reload
- `./frontend:/app/frontend` — React code mount for Vite HMR

## Notes
- `docker-compose.override.yml` was not created — the main `docker-compose.yml` uses environment variables with sensible defaults, making override unnecessary for dev
- HTTP/2 not configured — requires SSL/TLS certificates which is a production concern; Nginx currently serves plain HTTP on port 80 with WebSocket proxy support for both API and Vite HMR
- Nginx includes WebSocket `Upgrade` headers for both `/api/` and `/` routes
