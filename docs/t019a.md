# T019a — Internal Messaging System: Engine

- **Phase**: 1
- **Depends On**: T019, T008, T013
- **Estimated Effort**: 8 days

## What Is Being Built
Internal messaging system like Slack/Discord for company-internal collaboration. Channels (public/private/system/broadcast), direct messages, threaded conversations, file attachments, link previews (invoice, PO, etc.), system messages (approval requests, status updates), @mentions, emoji reactions, message search, read/unread tracking. All data stays within the company — no 3rd party tools.

## How It Will Be Built

### Backend (Django)
- **Models** (`apps/core/models.py`):
  - `Channel`: id, name, description, type (public/private/direct/group_dm/system/broadcast), created_by FK → User, is_archived, company FK, created_at, updated_at
  - `ChannelMember`: channel FK, user FK, role (owner/admin/member), last_read_at, notification_mute, joined_at, unique(channel, user)
  - `Message`: id, channel FK, sender FK → User, content (text), content_type (text/file/link/system), reply_to FK → Message (thread), link_type (optional — invoice/po/so/quote/do/asset/employee/project), link_id (optional — record UUID), is_edited, edited_at, is_deleted, created_at
  - `MessageAttachment`: id, message FK, file (FileField), file_name, file_size, mime_type, uploaded_at
  - `MessageReaction`: id, message FK, user FK, emoji, unique(message, user, emoji)
  - `MessageRead`: message FK, user FK, read_at, unique(message, user)

- **Service** (`apps/core/services/messaging_service.py`):
  - `create_channel(name, type, members, created_by)` — create channel
  - `add_member(channel_id, user_id, role)` — add member
  - `remove_member(channel_id, user_id)` — remove member
  - `send_message(channel_id, sender, content, content_type, reply_to, link_type, link_id)` — send message
  - `edit_message(message_id, content)` — edit (only sender)
  - `delete_message(message_id)` — soft delete (only sender or admin)
  - `add_reaction(message_id, user_id, emoji)` — toggle reaction
  - `remove_reaction(message_id, user_id, emoji)` — remove reaction
  - `mark_read(channel_id, user_id, message_id)` — mark as read up to message
  - `get_channels(user_id)` — channels user belongs to
  - `get_messages(channel_id, limit, before)` — paginated messages
  - `get_threads(message_id)` — replies to a message
  - `search_messages(query, channel_id, user_id)` — full-text search
  - `get_unread_counts(user_id)` — unread count per channel
  - `get_direct_channel(user1_id, user2_id)` — find or create DM channel

- **WebSocket Consumer** (`apps/core/consumers.py`):
  - `ChatConsumer` — handles real-time messaging
  - User joins channels on connect
  - Broadcasts messages to channel members
  - Handles typing indicators
  - Handles read receipts

- **System Message Integration**:
  ```python
  # When approval requested (T016):
  def post_approval_message(execution):
      channel = get_channel('approvals')
      send_system_message(
          channel,
          f"@{approver.name} Please approve {doc_type} {doc_number} ({amount})",
          link_type='approval',
          link_id=execution.id
      )

  # When document created:
  def post_document_message(doc_type, doc, channel):
      send_system_message(
          channel,
          f"New {doc_type} {doc.number} created for {doc.party.name}",
          link_type=doc_type,
          link_id=doc.id
      )
  ```

- **API** (`apps/core/api/messaging_api.py`):
  - `GET /api/v1/messaging/channels/` — list user's channels
  - `POST /api/v1/messaging/channels/` — create channel
  - `GET /api/v1/messaging/channels/{id}/` — channel detail
  - `POST /api/v1/messaging/channels/{id}/members/` — add member
  - `DELETE /api/v1/messaging/channels/{id}/members/{user_id}/` — remove member
  - `GET /api/v1/messaging/channels/{id}/messages/` — paginated messages
  - `POST /api/v1/messaging/channels/{id}/messages/` — send message
  - `PUT /api/v1/messaging/messages/{id}/` — edit message
  - `DELETE /api/v1/messaging/messages/{id}/` — delete message
  - `POST /api/v1/messaging/messages/{id}/reactions/` — add reaction
  - `DELETE /api/v1/messaging/messages/{id}/reactions/{emoji}/` — remove reaction
  - `GET /api/v1/messaging/messages/{id}/threads/` — get thread replies
  - `POST /api/v1/messaging/channels/{id}/read/` — mark as read
  - `GET /api/v1/messaging/unread/` — unread counts
  - `GET /api/v1/messaging/search/` — search messages
  - `POST /api/v1/messaging/channels/{id}/attachments/` — upload file
  - `GET /api/v1/messaging/dm/{user_id}/` — get or create DM channel

### Security Rules (MANDATORY)
- Internal users CANNOT access external portal channels
- External portal users CANNOT access internal channels
- Client A CANNOT see Client B's data
- Supplier A CANNOT see Supplier B's data
- File attachments are access-controlled (channel membership)
- Company-scoped: all queries filtered by company_id
- Link previews show minimal data to external users
