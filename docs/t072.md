# T071 — Work Orders

- **Phase**: 6
- **Depends On**: T062, T065, T067
- **Estimated Effort**: 5 days

## What Is Being Built
`WorkOrder` CRUD: BOM reference, quantity, start/end date, status. Material issue (component picking, backflush option). Labour time booking against operations. WO completion → finished goods receipt + backflush components. WO cost accumulation.

## How It Will Be Built

### Backend (Django)
- **Models** (`apps/mrp/models.py`):
  - `WorkOrder`: wo_number, item FK, bom FK, routing FK, quantity, quantity_completed, quantity_scrapped, status (draft/released/in_progress/completed/closed), planned_start_date, planned_end_date, actual_start_date, actual_end_date, company FK
  - `WorkOrderMaterial`: work_order FK, component_item FK, planned_qty, issued_qty, uom FK, backflush
  - `WorkOrderOperation`: work_order FK, operation FK, work_center FK, setup_time, run_time, labour_hours, status
  - `WorkOrderCost`: work_order FK, cost_type (material/labour/overhead), amount, description
- **Service**: CRUD, material issue, labour booking, completion (receipt + backflush), cost accumulation
- **API**: CRUD + issue + book + complete + cost endpoints

## Deliverables Checklist
- [ ] `WorkOrder`, `WorkOrderMaterial`, `WorkOrderOperation`, `WorkOrderCost` models
- [ ] Material issue (manual or backflush)
- [ ] Labour time booking
- [ ] WO completion → finished goods receipt
- [ ] Backflush component consumption
- [ ] Cost accumulation (material + labour + overhead)
- [ ] React WO pages

## Success Criteria
- [ ] Material issue reduces component stock
- [ ] Labour booking tracks hours per operation
- [ ] Completion creates finished goods stock movement
- [ ] Backflush consumes components automatically
- [ ] Total WO cost = material + labour + overhead
- [ ] All tests pass
