# T079 — Leave Management

- **Phase**: 7
- **Depends On**: T013, T072
- **Estimated Effort**: 4 days

## What Is Being Built
`LeaveType` (annual, sick, hospitalisation, maternity, paternity, unpaid, Haj, compassionate, marriage, study). `LeavePolicy` per grade (entitlement days, carry-forward, pro-rate for new joiners). Leave balance accrual. `LeaveApplication` with approval workflow. Leave calendar. Leave report.

## How It Will Be Built

### Backend (Django)
- **Models** (`apps/hrm/models.py`):
  - `LeaveType`: name, code, days_entitlement, is_paid, max_carry_forward, is_carry_forwardable, is_active, company FK
  - `LeavePolicy`: grade FK, leave_type FK, entitlement_days, carry_forward_days, max_consecutive_days, probation_entitlement, company FK
  - `LeaveBalance`: employee FK, leave_type FK, year, entitlement, taken, balance, carried_forward
  - `LeaveApplication`: employee FK, leave_type FK, start_date, end_date, total_days, reason, status (draft/submitted/approved/rejected/cancelled), approval_request FK, company FK
  - `LeaveCalendarEvent`: leave_application FK, date, day_number
- **Service**: balance accrual, application processing, approval, carry-forward
- **API**: Leave type/policy CRUD, application CRUD + submit + approve + reject, balance query, calendar

### Frontend (React)
- `LeaveApplicationFormPage` — apply for leave
- `LeaveBalancePage` — view balance per leave type
- `LeaveCalendarPage` — team calendar showing who's on leave
- `LeaveApprovalPage` — pending approvals for managers
