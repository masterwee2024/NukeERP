# T032 — Accounts Receivable: Customer Invoice

- **Phase**: 2
- **Depends On**: T013, T014, T018, T026, T041
- **Estimated Effort**: 8 days

## What Is Being Built
Customer invoice CRUD with line items, tax, SST number validation, GL posting. Multiple delivery consolidation. Aging analysis.

## How It Will Be Built

### Backend (Django)
- **Models**:
  - `Customer`: (shared with CRM) name, code, contact, address, payment_terms, credit_limit, GL_account FK, tax_code FK, SST_no, company FK, is_active
  - `CustomerInvoice`: customer FK, invoice_number, date, due_date, currency, exchange_rate, status, foreign_amount (amount in foreign currency), base_amount (amount in MYR = foreign_amount × exchange_rate), total, tax_total, grand_total, company FK
  - `CustomerInvoiceLine`: invoice FK, line_number, item FK, description, quantity, unit_price, discount_percent, amount, tax_code FK, tax_amount, GL_account FK
- **Service**: create, validate, submit, post (GL: DR AR control, CR revenue, CR tax payable), void
- **API**: Full CRUD + submit + post + void

## Deliverables Checklist
- [ ] `Customer`, `CustomerInvoice`, `CustomerInvoiceLine` models
- [ ] Invoice service with GL posting
- [ ] Tax calculation per line
- [ ] Aging analysis
- [ ] React list, form, and detail pages
- [ ] All CRUD actions use `useConfirm()` dialog

## Success Criteria
- [ ] Invoice creates correct GL entries (DR AR, CR Revenue, CR Tax)
- [ ] Tax calculation is accurate
- [ ] Aging buckets are correct (current, 30, 60, 90, 120+ days)
- [ ] Foreign currency invoice stores both foreign_amount and base_amount
- [ ] base_amount = foreign_amount × exchange_rate
- [ ] All tests pass
