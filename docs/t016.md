# T016 — Approval Workflow Engine

- **Phase**: 1
- **Depends On**: T009, T013
- **Estimated Effort**: 8 days

## What Is Being Built
Visual, configurable approval workflow engine with conditional routing, multi-level sequential/parallel approval, company-scoped workflows, creator≠approver enforcement, and integration with ConfirmDialog via `useApproval()` hook. Reusable across PO, invoice, leave, claims — any transaction requiring approval.

## Business Rules (MANDATORY)
1. **Company-scoped**: Workflows are per-company. Only users with `UserCompany` access can be approvers for that company's transactions.
2. **Creator ≠ Approver**: The user who creates a transaction cannot approve the same transaction. If all potential approvers are the creator, escalate to next level.
3. **Company access validation**: On every approval action, verify the approver has `UserCompany` access to the transaction's company.

## How It Will Be Built

### Backend (Django)
- **Models** (`apps/core/models.py`):
  - `WorkflowDefinition`: name, module (financial/scm/crm/mrp/hrm), document_type, version (auto-increment), flow_data (JSON — react-flow nodes/edges), is_active, company FK (null = global template), is_global_template, created_by FK, created_at, updated_at
  - `WorkflowNode`: workflow FK, node_id (react-flow ID), node_type (start/end/approve/condition/notify/action), label, position_x, position_y, config (JSON):
    - approve: `{ approvers: [{type:"role"|"user", id:UUID}], approval_type: "sequential"|"parallel", min_approvals: int, timeout_hours: int, escalation_node_id: string }`
    - condition: `{ field: string, operator: ">"|"<"|">="|"<="|"=="|"!="|"in"|"not_in", value: any, true_node_id: string, false_node_id: string }`
    - notify: `{ recipients: [{type:"role"|"user", id:UUID}], template: string, channels: ["push","email","sms","in_app"] }`
    - action: `{ field: string, value: any, description: string }`
  - `WorkflowEdge`: workflow FK, source_node_id, target_node_id, label, condition (JSON)
  - `WorkflowExecution`: id, workflow FK, document_type, document_id (UUID), current_node_id, status (pending/approved/rejected/cancelled/completed), requester FK → User, created_by FK → User (who created transaction), company FK → Company, started_at, completed_at, metadata (JSON)
  - `WorkflowExecutionStep`: execution FK, node FK, approver FK → User, action (approve/reject/return/delegate), comment, timestamp, status (pending/completed/skipped), ip_address, delegated_to FK (optional)

- **Service** (`apps/core/services/workflow_service.py`):
  - `create_execution(workflow, document_type, document_id, requester, company)` — create execution, store created_by = requester, advance to first approve/condition node
  - `resolve_approvers(node, execution)` — get potential approvers, filter by UserCompany access, exclude created_by (creator≠approver), return valid approvers
  - `process_action(execution_id, approver, action, comment, ip)` — validate: approver has company access, approver ≠ created_by, record step, advance/reject/escalate
  - `evaluate_condition(node, execution)` — evaluate condition against document data, return true_node or false_node
  - `escalate(execution)` — move to escalation node or next level when timeout or no valid approvers
  - `get_pending(user)` — all pending approvals for user across all companies they have access to
  - `get_history(document_type, document_id)` — full execution history
  - `get_execution_context(execution_id)` — full document data + approval history for approval page

- **API** (`apps/core/api/workflow_api.py`):
  - `POST /api/v1/workflows/execute/` — start execution (submit for approval)
  - `POST /api/v1/workflows/executions/{id}/approve/` — approve
  - `POST /api/v1/workflows/executions/{id}/reject/` — reject
  - `POST /api/v1/workflows/executions/{id}/delegate/` — delegate
  - `GET /api/v1/workflows/executions/pending/` — pending approvals list
  - `GET /api/v1/workflows/executions/{id}/context/` — full context for approval
  - `GET /api/v1/workflows/history/{doc_type}/{doc_id}/` — approval history
  - `GET /api/v1/admin/workflows/` — list workflows
  - `POST /api/v1/admin/workflows/` — create workflow
  - `PUT /api/v1/admin/workflows/{id}/` — update workflow
  - `POST /api/v1/admin/workflows/{id}/clone/` — clone to company

### Frontend (React)
- **Approval Panel**: `frontend/src/components/approval/ApprovalPanel.tsx`
  - Shows workflow status, current node, who needs to approve
  - Approve/Reject/Return buttons with comment
  - Delegation option
  - All actions use `useConfirm()` via `useApproval()` hook

- **Approval Page**: `frontend/src/components/approval/ApprovalPage.tsx`
  - Full document context for approval decision
  - Previous approval steps shown
  - Approve/Reject/Delegate actions

### Integration with ConfirmDialog
- Every CRUD component uses `useApproval()` hook
- `submit()` shows ConfirmDialog → triggers workflow
- `approve()` shows ConfirmDialog → processes approval
- `reject()` shows ConfirmDialog with comment → processes rejection
- One codebase, one pattern, no scattered logic
